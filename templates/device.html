Enabling the trained model

Export the multimodal model to TFLite, place it in models/, then start the app with MODEL_PATH pointing at it. The app switches over automatically and every prediction is re-tagged as trained-model. If the file fails to load, it falls back to the baseline rather than serving nothing.

{# --- integration guide ---------------------------------------------- #}

Raspberry Pi integration

The Pi pushes readings to this server. Nothing is polled from the device, so the agent works behind NAT and can buffer while offline.

Send one reading

curl -X POST {{ request.url_root }}api/device/v1/readings \ -H "Authorization: Bearer <device-token>" \ -H "Content-Type: application/json" \ -d '{"temperature_c": 24.8, "humidity_pct": 61.2}'

Send a buffered batch

POST /api/device/v1/readings/batch {"readings": [{"temperature_c": 24.8, "humidity_pct": 61.2, "recorded_at": "2026-08-25T10:30:00Z"}, ...]}

Upload a camera frame

POST /api/device/v1/captures (multipart: image=<file>, item_id=<id>)

A ready-made agent lives in tools/pi_agent.py. It reads the BMP280 and SHT31 over I2C when the libraries are present, buffers to disk when the network drops, and posts on an interval.
